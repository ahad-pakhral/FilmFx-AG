# Plan 3: Image I/O, Error Handling, and Basic UI
**Phase**: 1
**Goal**: Handle image importing (downsampled by OS max 1080p), texture upload with bilinear filtering, CPU memory discarding, and user-facing error boundaries.

## Requirements
IO-01, UI-01, PIPE-01

## Tasks

```xml
<tasks>
  <task id="1">
    <description>Implement native OS image picker and downsampling (if larger than 1080p) before passing the bitmap array to the C++ engine.</description>
  </task>
  <task id="2">
    <description>Upload the bitmap to the GPU preview texture using Bilinear filtering, then immediately discard the CPU bitmap data.</description>
  </task>
  <task id="3">
    <description>Implement error handling boundaries: Friendly UI error if GPU unsupported, automatic downscale/retry on OOM, and a 'restart renderer' button toast for runtime shader crashes.</description>
  </task>
  <task id="4">
    <description>Create the basic dark, photo-centric shell UI with a placeholder bottom control area.</description>
  </task>
</tasks>
```

## Verification
1. Loading an extreme high-res image (e.g. 50MP) does not crash the app, but loads quickly as a 1080p proxy.
2. The UI is dark-themed and the image is visible in the center.
3. Forcing a runtime shader error correctly displays the recovery toast rather than a hard crash.

## Must Haves
- CPU memory must not contain the image bitmap after it is securely on the GPU.
- The user can pick an image and see it rendered at 30fps+.
